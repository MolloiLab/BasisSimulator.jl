Helical Scanning: Narrow Collimation, Long Coverage

One keyword, pitch, turns any protocol into a spiral scan: here a 20 mm helix and three 160 mm volume-axial stations cover the same 30 cm of a phantom that changes along z.

Before spiral CT, long coverage meant step-and-shoot: scan a slab, move the table, scan the next. Each station is a clean axial scan, but every station has cone-beam edges, and the stitched volume can step at a station boundary. A helical scan instead sweeps a narrow beam past every slice continuously: each z position is, at some moment of the spiral, at the centre of the beam.

The Two Scans at a Glance

Both cover a 30 cm reconstructed z-slab on a wide-cone 256 × 0.625 mm (16 cm) volume scanner, with the tube currents chosen so that the two deliver the same total beam width × current × time:

ScanCollimationRotationsTable
volume axial160 mm (the full detector)3 × axialsteps 10 cm between stations
helical20 mm (one eighth)16 turnsglides at pitch 1.0

The forward projection is the anti-aliased :dd_fast projector, and helical costs it nothing: the projectors consume per-view source and detector arrays, and a helix is a z-ramp in those arrays. Both scans integrate each view over the arc the gantry turns while the detector reads it (view_samples = 5); on the helix each sub-view is also advanced along z by its share of the table feed. Each simulate! also reports its dose, so the two can be compared in CTDIvol and DLP as well as in image quality.

    """A blank drawing area at `position`: equal scales, no axes, limits `(x0, x1, y0, y1)`."""
    function canvas(position, limits; background = COLORS.paper)
        ax = Mke.Axis(position; aspect = Mke.DataAspect(), backgroundcolor = background)
        Mke.hidedecorations!(ax)
        Mke.hidespines!(ax)
        Mke.limits!(ax, limits...)
        return ax
    end

    """The corners of a rectangle centred at `c`, `w` × `h`, its corners rounded by `r`."""
    function rounded_rect(c, w, h, r)
        x0, y0, x1, y1 = c[1] - w / 2, c[2] - h / 2, c[1] + w / 2, c[2] + h / 2
        r = min(r, w / 2, h / 2)
        arc(cx, cy, θ0) = [
            Mke.Point2f(cx + r * cos(θ), cy + r * sin(θ))
            for θ in range(θ0, θ0 + π / 2; length = 8)
        ]
        return vcat(
            arc(x1 - r, y0 + r, -π / 2),
            arc(x1 - r, y1 - r, 0.0),
            arc(x0 + r, y1 - r, π / 2),
            arc(x0 + r, y0 + r, π),
        )
    end

    """A straight arrow from `a` to `b`; `head` is the arrowhead's size in pixels."""
    function arrow!(
        ax,
        a,
        b;
        color = COLORS.muted,
        linewidth = 2.5,
        head = 15,
        linestyle = :solid,
    )
        a, b = Mke.Point2f(a), Mke.Point2f(b)
        Mke.lines!(ax, [a, b]; color, linewidth, linestyle)
        t = b - a
        Mke.scatter!(

            [b];
            marker = :utriangle,
            markersize = head,
            rotation = atan(t[2], t[1]) - π / 2,
            color,
            markerspace = :pixel,
        )
        return nothing
    end

    """
    A box in a flow chart: centred at `c`, `w` × `h`, a bold `title` and an optional smaller

    """
    A flow chart: `nodes` maps a key to `(x, y, title, subtitle, accent)` (subtitle and accent
    optional), `edges` lists `from => to` pairs, drawn as arrows between the boxes' edges, and
    `labels` (optional) puts a note on an edge. Returns the canvas.
    """
    function flow_chart!(position, nodes, edges; limits, w = 3.0, h = 1.0, labels = Dict())
        ax = canvas(position, limits)
        box(key) = nodes[key]
        function port(from, to)
            a, b = box(from), box(to)
            if abs(b[2] - a[2]) < 1.0e-6
                # side by side
                s = sign(b[1] - a[1])
                return (a[1] + s * w / 2, a[2]), (b[1] - s * w / 2, b[2])
            elseif abs(b[1] - a[1]) < 1.0e-6
                # one above the other
                s = sign(b[2] - a[2])
                return (a[1], a[2] + s * h / 2), (b[1], b[2] - s * h / 2)
            else
                # leave sideways, arrive on the facing side
                s = sign(b[1] - a[1])
                return (a[1] + s * w / 2, a[2]), (b[1] - s * w / 2, b[2])
            end
        end
        for (from, to) in edges
            p, q = port(from, to)
            if abs(p[1] - q[1]) < 1.0e-6 || abs(p[2] - q[2]) < 1.0e-6
                # straight across or straight down
                arrow!(ax, p, q)
            else
                # a right-angled connector: across to the gap's middle, along it, then in
                mx = (p[1] + q[1]) / 2
                Mke.lines!(
                    ax,
                    Mke.Point2f[p, (mx, p[2]), (mx, q[2])];
                    color = COLORS.muted,
                    linewidth = 2.5,
                )
                arrow!(ax, (mx, q[2]), q)
            end
            haskey(labels, from => to) &&
                Mke.text!(
                    ax,
                    (p[1] + q[1]) / 2,
                    q[2] + 0.12;
                    text = labels[from => to],
                    align = (:center, :bottom),
                    fontsize = 15,
                    color = COLORS.muted,
                )
        end
        for (_, n) in nodes
            node!(
                ax,
                (n[1], n[2]),
                n[3];
                subtitle = length(n) >= 4 ? n[4] : "",
                accent = length(n) >= 5 ? n[5] : COLORS.violet,
                w,
                h,
            )
        end
        return ax
    end

    θ(z) = 2π * (z - z0) / 12
    for front in (false, true)
        points = [
            (sin(θ(z)) >= 0) == front ? Mke.Point2f(z, 7cos(θ(z))) : Mke.Point2f(NaN, NaN)
            for z in zs

        Mke.lines!(ax, points; color = (COLORS.beam, front ? 1.0 : 0.35), linewidth = 9)

helix!

The helical source path on ax, z (cm) across: turns turns of radius radius round the patient over travel cm of table, solid in front and faint behind, with the narrow beam of width beam at the middle of the scan.

"""
The helical source path on `ax`, z (cm) across: `turns` turns of radius `radius` round the
patient over `travel` cm of table, solid in front and faint behind, with the narrow beam of
width `beam` at the middle of the scan.
"""
function helix!(ax; turns = 16, travel = 32.0, radius = 7.0, beam = 2.0, dark = false)
    ink = dark ? COLORS.night_ink : COLORS.ink
    Mke.poly!(
        ax,
        Mke.Rect2f(-travel / 2, -radius + 2.2, travel, 2radius - 4.4);
        color = (COLORS.blue, dark ? 0.45 : 0.3),
    )
    t = range(0, 1; length = round(Int, 120 * turns))
    z = @. -travel / 2 + travel * t
    φ = @. 2π * turns * t
    for front in (false, true)
        points = [
            (sin(p) >= 0) == front ?
                Mke.Point2f(zz, radius * cos(p)) :
                Mke.Point2f(NaN, NaN)
            for (zz, p) in zip(z, φ)
        ]
        Mke.lines!(
            ax,
            points;
            color = (COLORS.beam, front ? 1.0 : 0.3),
            linewidth = front ? 2.5 : 1.5,
        )
    end
    # the beam at one moment: a source on top, a fan as wide as the collimation below it
    Mke.poly!(
        ax,
        Mke.Point2f[(0, radius), (-beam / 2, -radius), (beam / 2, -radius)];
        color = (COLORS.beam, 0.45),
    )
    Mke.scatter!(ax, [Mke.Point2f(0, radius)]; marker = :rect, markersize = 18, color = ink)
    Mke.lines!(
        ax,
        [-beam / 2, beam / 2],
        [-radius, -radius];
        color = COLORS.cyan,
        linewidth = 8,
    )
    arrow!(
        ax,
        (-travel / 2, -radius - 1.6),
        (travel / 2, -radius - 1.6);
        color = ink,
        head = 13,
    )
    return ax
end

1. A Phantom That Changes Along z

Two design rules. A uniform cylinder would look the same at every slice, useless for judging long-z fidelity, so every slice must differ. And no high-Z inserts: beam hardening is its own topic (notebook 10), and here it would only confound the geometry comparison.

  • a 24 cm water body, 36 cm long (coarse 2.3 mm in-plane and 2 mm z voxels);

  • a lung-density rod (about −700 HU, radiologically soft) that winds helically round the body axis, one turn per 12 cm of z, so its angle tags every slice;

  • an adipose cone (about −90 HU) on the axis, its radius tapering from 4 cm to 0 across the slab, so its diameter tags every slice.

phantom_data = let
    n = 128     # in-plane grid
    nz = 180    # 2 mm z-voxels → 36 cm slab
    fov = 30.0  # cm, in-plane phantom extent
    zext = 36.0 # cm, phantom z extent
    vox = fov / n
    voxz = zext / nz
    mask = zeros(UInt8, n, n, nz)
    c = (n + 1) / 2
    r_body = 12.0 / vox # 24 cm water body
    for k in 1:nz, j in 1:n, i in 1:n
        if (i - c)^2 + (j - c)^2 <= r_body^2
            mask[i, j, k] = 1
        end
    end
    # helically winding lung-density rod: r = 7 cm, one turn per 12 cm of z
    for k in 1:nz
        θ = 2π * (k * voxz) / 12.0
        cx = c + (7.0 / vox) * cos(θ)
        cy = c + (7.0 / vox) * sin(θ)
        r = 1.0 / vox # 2 cm diameter rod
        for j in 1:n, i in 1:n
            if (i - cx)^2 + (j - cy)^2 <= r^2 && mask[i, j, k] == 1
                mask[i, j, k] = 2
            end
        end
    end
    # central adipose cone: radius tapers 4 cm → 0 across the slab
    for k in 1:nz
        r = (4.0 * (1 - (k - 1) / (nz - 1))) / vox
        for j in 1:n, i in 1:n
            if (i - c)^2 + (j - c)^2 <= r^2 && mask[i, j, k] == 1
                mask[i, j, k] = 3
            end
        end
    end
    (mask = mask, vox = vox, voxz = voxz, n = n, nz = nz, zext = zext)
end;
phantom_materials = Dict(
    1 => BS.XA.Materials.water,
    2 => BS.XA.Materials.lung,
    3 => BS.XA.Materials.adipose,
);
phantom = BS.Phantom(
    to_gpu(phantom_data.mask),
    phantom_materials,
    (phantom_data.vox, phantom_data.vox, phantom_data.voxz),
);

2. The Helical Scan: pitch Is the Whole API

IEC pitch is the table feed per rotation over the active collimation. With 20 mm collimation (32 of the scanner's 256 × 0.625 mm rows), pitch 1.0 and 16 rotations, the table travels

$$\text{travel} = \text{pitch} \times \text{collimation} \times n_\text{rot} = 1.0 \times 20\,\text{mm} \times 16 = 32\,\text{cm}.$$

Everything else (Phantom, the scanner, SimOptions, ReconOptions, simulate!, the corrections, the reconstruction call) is the same as in an axial workflow.

The scanner is the GE Revolution Apex (REVOLUTION_APEX), whose 256 × 0.625 mm rows are the volume detector this comparison needs, with the notebook's 512 one-millimetre columns in place of its 834 so the scans cost what they did. Both scans include the patient's scatter (on by default), from the Geant4 kernels the Apex names, and the DAS's scatter correction; the kernels are made for one scanner's distances, so the scans run at the Apex's 625.6 and 1100 mm.

3. The Reconstruction Chain

One water beam-hardening correction (BHC) per protocol, calibrated on that acquisition's geometry, then per reconstruction: sinogram-domain water BHC, reconstruction, and HU with the BHC's own $\mu_\text{water}$. reconstruct! recognises a helical geometry and runs rebinned WFBP (Stierstorfer et al. 2004, the production spiral algorithm family); an axial one runs FDK. Quantum and electronic noise are already in the simulated counts.

"""
    corrected_recon(sino_gpu, geom, matrix_size, bhc) -> Array{Float32,3} (HU)

Water BHC → reconstruction → HU for one sinogram. A helical `geom` dispatches to WFBP inside
`reconstruct!`.
"""
function corrected_recon(sino_gpu, geom, matrix_size, bhc)
    sino = BS.apply_bhc_water(sino_gpu, bhc)
    ws_fdk = BS.create_fdk_recon_workspace(sino, geom, matrix_size)
    recon_μ = BS.reconstruct!(ws_fdk, sino, geom)
    return Float32.(BS.to_hounsfield(Array(recon_μ); μ_water = bhc.μ_water_ref))
end;

4. Run Both Acquisitions

Helical: one simulate!, one reconstruction. Volume axial (step-and-shoot): three 10 cm reconstruction stations. For each, the table (here, the phantom window) moves so that the station is centred on the isocentre; the three slabs are then stitched at $z = ±5$ cm. The 16 cm beams of neighbouring stations overlap by 6 cm, so each station's dose is reported with a 10 cm table increment.

helical_result = let
    ws = BS.create_workspace(scanner, protocol_helical, sim_opts, recon_opts, phantom)
    t = @elapsed (sim = BS.simulate!(ws, phantom, protocol_helical, sim_opts))
    bhc = BS.calibrate_bhc_water(sim_opts, protocol_helical; scanner, geom = ws.geom)
    t += @elapsed (hu = corrected_recon(ws.sinogram, ws.geom, recon_opts.matrix_size, bhc))
    n_views = ws.geom.n_angles
    ws = nothing
    GC.gc()
    (hu = hu, t = t, dose = sim.dose, n_views = n_views)
end;

8. What This Shows, and Its Scope

  • :dd_fast needed zero changes for helical. The projectors consume per-view geometry arrays (the same representation as ASTRA's cone_vec and CatSim's internal trajectory); the helix lives entirely in those arrays, and so do the sub-views of the view integration, each rotated and advanced along $z$ with the table.

  • Helical reconstruction is rebinned WFBP (Stierstorfer et al., Phys Med Biol 49:2209, 2004): row-wise fan→parallel rebinning, parallel ramp filtering, and aperture-weighted (cos², plateau $Q = 0.7$) wedge backprojection with per-half-turn redundancy normalisation. This is the production spiral-CT algorithm family (Siemens WFBP; UCLA FreeCT), and reconstruct! / fdk_reconstruct dispatch to it whenever is_helical(geom).

  • Both scans got identical corrections. Exposure is matched by beam width × current: 16 × 20 mm × 200 mA against 3 × 160 mm × 133⅓ mA at equal rotation time. That is an acquisition-integral match, not equal CTDIvol or equal noise per slice; the dose table in section 4 gives both scans' CTDIvol and DLP.

  • Hybrid IR works on helical unchanged: matched forward and backprojection are geometry-general, subsets are angular-interleaved, and the HIR FDK initialisation routes through WFBP.

  • Windmill artifacts round sharp $z$ edges at high pitch are physics (longitudinal sampling), not a defect of the reconstruction.

  • Wall clock (this page was rendered on an NVIDIA RTX PRO 6000, CUDA): helical (5760 views, simulation + corrections + WFBP) 27.2 s; volume axial (3 stations × 360 views) 3.7 s. Both include first-call compilation.

Summary

pitch and n_rotations are the only additions that turn the axial acquisition into a centred helical trajectory; :dd_fast projects it unchanged, and reconstruct! sends helical geometries to rebinned WFBP and axial stations to FDK.
